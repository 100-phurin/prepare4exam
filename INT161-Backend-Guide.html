      HTTP Programming Basics

      โครงสร้าง request/response, โมดูล http ของ Node, CJS กับ ESM และการอ่านค่าจาก URL

      HTTP Request เก็บข้อมูลได้ 3 ที่

      • Method บอกว่าจะทำอะไร (GET, POST, …)
      • Headers ข้อมูลประกอบ เช่น Content-Type, Host
      • Body ข้อมูลหลัก เช่น JSON ตอน POST/PUT

      ส่วน URL เองก็มี path และ query string ด้วย

      HTTP Response มี 3 ส่วน

      • Status line บรรทัดแรก เช่น HTTP/1.1 200 OK
      • Headers
      • Message body (payload)

      Node.js ทำงานยังไง (Event Loop)

      1. client ส่ง request เข้ามา (อาจเป็นงาน blocking หรือ non-blocking เช่น query/update/delete)
      2. Node รับ request ไปต่อคิวใน Event Queue
      3. Event Loop หยิบทีละอัน ถ้าเป็นงานง่ายที่ไม่ต้องรอทรัพยากรภายนอก (non-blocking) ก็ทำแล้วตอบกลับเลย

      Introduction to RESTful API

      REST = REpresentational State Transfer โดย Roy Fielding · server เปิดให้เข้าถึง resource แต่ละ resource ระบุด้วย URI และส่งเป็น representation (นิยม JSON)

      6 หลักการ (constraints) ของ REST

      1. Client–Server

      แยก client กับ server ออกจากกัน server มี web service ให้บริการ client ส่ง request มา server จะปฏิเสธหรือตอบสนองก็ได้

      2. Stateless

      ทุก request ต้องมีข้อมูลครบในตัวเอง server ห้ามอาศัย context ที่เก็บไว้จาก request ก่อนหน้า client ต้องเก็บ session state เอง

      3. Uniform Interface

      ใช้ HTTP verb มาตรฐานจัดการ resource: POST สร้าง, GET อ่าน, PUT แก้ไข, DELETE ลบ (รายละเอียดด้านล่าง)

      4. Layered System

      ระบบแบ่งเป็นชั้น แต่ละชั้นเห็นแค่ชั้นที่ติดกัน client ไม่รู้ว่าคุยกับ server ปลายทางหรือตัวกลาง

      5. Cacheable

      response ต้องบอก (ทางตรงหรืออ้อม) ว่า cache ได้หรือไม่ ถ้าได้ client นำ response มาใช้ซ้ำกับ request เดียวกันในช่วงเวลาที่กำหนด

      6. Code on Demand (optional)

      server ส่งโค้ด (script/applet) ให้ client รันเพื่อขยายความสามารถได้ เป็นข้อเดียวที่ไม่บังคับ

      Uniform Interface: 4 เสาหลัก

      เสาหลักความหมาย
      Resource IdentificationURI บอก resource (คำนาม) ไม่ใช่ action เช่น /api/v1/users
      Manipulation via Representationsแลกเปลี่ยน state ด้วยรูปแบบมาตรฐาน (JSON)
      Self-Descriptive Messagesใช้ HTTP method และ header มาตรฐาน เช่น Content-Type: application/json
      HATEOASใส่ลิงก์ (hypermedia) ใน response เพื่อบอก client ว่าทำอะไรต่อได้

      ออกแบบ endpoint ให้ถูกหลัก

      MethodURIความหมาย
      GET/api/productsดึงสินค้าทั้งหมด (collection)
      GET/api/products/1ดึงสินค้า id = 1 (singleton)
      GET/api/products/1/ordersดึง orders ของสินค้า id = 1 (sub-collection)
      POST/api/productsเพิ่มสินค้าใหม่ (ส่ง body)
      PUT/api/products/1แก้ไขสินค้า id = 1 (ส่ง body)
      DELETE/api/products/1ลบสินค้า id = 1

      ✓ ควรทำ

      • URI ลงท้ายด้วยคำนาม และใช้พหูพจน์ เสมอ (/users)
      • ให้ HTTP verb เป็นตัวบอก action
      • ส่ง status code ที่ถูกต้องทั้งตอนสำเร็จและ error
      • ดู endpoint + method แล้วรู้ทันทีว่าทำอะไร

      ✗ ไม่ควรทำ

      • /getUsers, /createProduct (มีคำกริยาใน URI)
      • /user/1 ปนกับ /users (เอกพจน์ปนพหูพจน์)
      • ตอบ 200 ทุกกรณีแล้วใส่ error ไว้ใน body

      Layered System ในโค้ด

      src/ ├── server.js → ตั้งค่า HTTP server ├── router.js → จับคู่ route + จัดการ HTTP (Controller) ├── services/ → business logic (ไม่ผูกกับ framework) └── repositories/ → เข้าถึงข้อมูล (ไฟล์ / DB)
      ประโยชน์ของการแบ่งชั้น: Scalability (เพิ่ม cache/load balancer ได้โดย client ไม่ต้องแก้), Separation of Concerns (แยกการ parse HTTP ออกจาก business logic และ database) และ Security

      Middleware

      Middleware คือฟังก์ชัน (req, res, next) ที่ทำงานก่อนถึง router เช่น log, parse body, ตรวจสิทธิ์, validate, เปิด CORS ทำงานเรียงตามลำดับที่ app.use()

      • เรียก next() → ส่งต่อให้ middleware ตัวถัดไป
      • เรียก res.send() / res.json() → จบ ส่ง response กลับ
      • เรียก next(err) → ข้ามไป error-handling middleware ทันที

      ประเภท: Application-level, Router-level, Error-handling, Built-in (express.json()), Third-party

      src/repositories/subject-repo.js
      import pool from '../configs/db-config.js';

export async function findAll() {
  const [rows] = await pool.query('SELECT * FROM subjects');
  return rows;
}

export async function findById(id) {
  const [rows] = await pool.query('SELECT * FROM subjects WHERE id = ?', [id]);
  return rows.length === 0 ? null : rows[0];
}

export async function create(subject) {
  const [result] = await pool.query(
    'INSERT INTO subjects (subject_code, subject_title, credit) VALUES (?, ?, ?)',
    [subject.code, subject.title, subject.credit]);
  return findById(result.insertId);
}

export async function update(id, subject) {
  const [result] = await pool.query(
    'UPDATE subjects SET subject_code = ?, subject_title = ?, credit = ? WHERE id = ?',
    [subject.code, subject.title, subject.credit, id]);
  if (result.affectedRows === 0) return null;
  return findById(id);
}

export async function remove(id) {
  const [result] = await pool.query('DELETE FROM subjects WHERE id = ?', [id]);
  return result.affectedRows > 0;
}

      router.js · getBody()
      function getBody(request) {
  return new Promise((resolve, reject) => {
    let body = '';
    request.on('data', chunk => { body += chunk.toString(); }); // รับทีละ chunk
    request.on('end', () => resolve(body ? JSON.parse(body) : null)); // ครบแล้ว parse
    request.on('error', err => reject(err));
  });
}

      Validation และ Error Handling

      ถ้า error ถูก throw แล้วไม่มีใคร catch, Node จะจบ process (process.exit(1)) ทั้ง server ล่ม การจัดการ error จึงเป็นเรื่องบังคับ

      ทำไมต้องจัดการ error

      • กัน app crash / downtime
      • ข้อความ error ที่ผู้ใช้เข้าใจ
      • ไม่หลุด stack trace / ข้อมูลลับ
      • ช่วย debug, monitor, แจ้งเตือน

      ประเภท error

      • Programming error บั๊ก logic เช่น TypeError
      • Operational error network timeout, DB ล่ม, ไม่พบไฟล์
      • Expected vs Unexpected อันที่คาดไว้ต้องจัดการให้เรียบร้อย

      Error propagation

      error ที่เกิดในฟังก์ชันจะถูกส่งขึ้นไปตาม call stack (b → a → main) จนกว่าจะมีคน catch ถ้าไม่มีใคร catch เลยจนถึง global scope โปรแกรมจะหยุด ในระบบเลเยอร์ก็เหมือนกัน: Repository throw → Service ไม่ catch → Controller ส่ง next(err) → error middleware ตอบกลับ

      Property ของ Error object

      • message ข้อความอธิบาย
      • name ชนิด เช่น "TypeError"
      • stack stack trace (ไม่เป็นมาตรฐานแต่ทุกที่รองรับ)
      • code รหัส system error เช่น "EACCES", "ENOENT"
      • errno ตัวเลขของ system error

      Error middleware ต่างจาก middleware ปกติ

      ปกติ: (req, res, next) 3 ตัว

      Error: (err, req, res, next) 4 ตัว Express ดูจากจำนวน parameter

      ต้องวางไว้ท้ายสุด หลัง route ทั้งหมด ถ้าไม่เขียนเลย Express จะตอบเป็น HTML พร้อม stack trace

      src/middlewares/error-handler.js
      export class AppError extends Error {
  static errors = { 400: 'BAD_REQUEST', 401: 'UNAUTHORIZED', 403: 'FORBIDDEN',
                    404: 'NOT_FOUND', 409: 'CONFLICT', 500: 'INTERNAL_SERVER_ERROR' };
  constructor(message, statusCode = 500) {
    super(message);
    this.statusCode = statusCode;
    this.error = AppError.errors[statusCode];
    this.isOperational = true;
    Error.captureStackTrace(this, this.constructor);
  }
}

// ไม่มี route ไหนตรง → 404
export function notFound(req, res, next) {
  next(new AppError(`Route ${req.method} ${req.originalUrl} not found`, 404));
}

// error-handling middleware (4 parameters) วางท้ายสุดใน app.js
export function errorHandler(err, req, res, next) {
  const status = err.statusCode || err.status || 500;
  res.status(status).json({
    error: err.error || AppError.errors[status] || err.code,
    statusCode: status,
    message: err.message,
    path: req.originalUrl,
    timestamp: new Date().toISOString(),
  });
}

      Pagination และ DTO

      แบ่งข้อมูลเป็นหน้าเพื่อลดภาระ DB, หน่วยความจำ และ network และใช้ DTO คุมหน้าตาข้อมูลที่ส่งออกไป

      สูตรหัวใจ

      OFFSET = (page − 1) × limit
      pagelimitoffsetได้แถวที่
      11001–10
      2101011–20
      3102021–30
      9108081–90

      เครื่องคิด Pagination

      INTERACTIVE

      ลองใส่ page = -3 หรือ limit = 500 เพื่อดูว่า Math.max / Math.min ช่วยกันค่าผิดยังไง

      ลำดับการทำงาน

      1. client ส่ง GET /api/products?page=2&limit=20
      2. middleware ตรวจ page/limit แล้วคำนวณ offset เก็บไว้ใน req.pagination
      3. repository query ด้วย LIMIT ? OFFSET ? และ COUNT(*) หาจำนวนทั้งหมด
      4. ส่ง data พร้อม pagination metadata กลับไป

      Best practices

      • page ต้อง ≥ 1 → Math.max(parseInt(page), 1)
      • จำกัด limit สูงสุด เช่น 100 → Math.min(parseInt(limit), 100)
      • ใช้ prepared statement
      • ทำ index คอลัมน์ที่ใช้ filter/sort
      • ถ้าผู้ใช้เข้าหน้าลึกมาก ๆ พิจารณา cursor pagination

      Metadata ที่ควรส่ง

      • totalPages = Math.ceil(total / limit)
      • hasNextPage = page * limit < total
      • hasPrevPage = page > 1

      ต้องรู้ totalItems ก่อน จึงต้อง query SELECT COUNT(*) AS total แยกอีกครั้ง

      src/middlewares/pagination-middleware.js
      export const queryParser = () => (req, res, next) => {
  const query = req.query || {};
  if (query.page === undefined || query.limit === undefined) {
    req.pagination = null;            // ไม่ขอแบ่งหน้า → ส่งทั้งหมด
    return next();
  }
  const page  = Math.max(parseInt(query.page)  || 1, 1);    // ไม่ให้ติดลบ / NaN
  const limit = Math.min(parseInt(query.limit) || 20, 100); // ไม่เกิน 100
  const offset = (page - 1) * limit;   // ใช้ limit ที่ผ่านการตรวจแล้ว
  req.pagination = { page, limit, offset };
  next();
};

      DTO (Data Transfer Object)

      DTO คือ object ที่กำหนดรูปร่างของข้อมูลที่ส่งข้ามเลเยอร์/ออกไปทาง API แยก "สัญญาของ API" ออกจาก "โครงสร้างตารางในฐานข้อมูล" ข้อมูลจะถูก map จาก entity → DTO ผ่าน mapper และจาก entity เดียวทำ DTO ได้หลายแบบ (เช่น summary กับ detail)

      Entity (ในฐานข้อมูล)

      id, name, email, password_hash, role, created_at

      Response DTO (ส่งออก)

      id, name, email, role

      ห้ามส่ง password_hash ออกไปเด็ดขาด

      ทำไมใช้ DTO

      • กันไม่ให้ field ลับหลุดออกไปโดยไม่ตั้งใจ
      • response หน้าตาสม่ำเสมอ
      • validate และเขียนเอกสาร API ง่ายขึ้น
      • ลด coupling ระหว่าง DB กับ client (เปลี่ยนชื่อคอลัมน์ได้โดย API ไม่เปลี่ยน)
      src/mappers/product-mapper.js
      export default class ProductMapper {
  // ข้อมูลย่อ (ใช้ตอน list)
  static toSummaryDTO(entity) {
    return {
      id: entity.productCode,
      name: entity.productName,
      scale: entity.productScale,
      retailPrice: entity.MSRP,
    };
  }
  // ข้อมูลเต็ม (ใช้ตอนดูทีละชิ้น): เปลี่ยนชื่อ field แล้วตัดของเดิมออก
  static toDetailDTO(entity) {
    const { MSRP, buyPrice, ...data } = entity;
    return { ...data, retailPrice: MSRP, price: buyPrice };
  }
  static map(entity, view = 'full') {
    return view === 'summary' ? this.toSummaryDTO(entity) : this.toDetailDTO(entity);
  }
  static maps(entities, view = 'summary') {
    const list = entities.map(e => this.map(e, view));
    if (entities.totalItems !== undefined) list.totalItems = entities.totalItems; // พก total ไปด้วย
    return list;
  }
}
      src/mappers/api-response.js
      export function apiResponse(res, data, pagination = null, status = 200) {
  if (!pagination) {
    return res.status(status).json({ success: true, data, timestamp: new Date().toISOString() });
  }
  const { page, limit } = pagination;
  const total = data.totalItems;
  return res.status(status).json({
    success: true,
    data,
    pagination: {
      total, page, limit,
      totalPages: Math.ceil(total / limit),
      hasNextPage: page * limit < total,
      hasPrevPage: page > 1,
    },
    timestamp: new Date().toISOString(),
  });
}
